# AI 跳绳训练 · 实现计划（v1.4.0 起）

> 需求来源：资料库文档《交给另一个AI-完整指令》（2026-11-26 读取）。
> 这份文件是**落地版**：把需求翻成「在这个仓库里怎么一步步做」，并记录每一步的状态。

---

## 一、需求一句话

训练页保持现在这一页不动，在它之上把 **计数 → 录像 → AI 动作分析** 串成一条完整流程。
两条铁律：

1. **AI 分析跟模式走**：定时跳 / 定数跳 有；花样跳 / 自由跳 没有。
2. **实时计数画面绝不画骨架 / 关键点 / 角度**，评分只出现在回放页。

## 三、分批计划

### 批 1｜训练页补全（不需要原生能力，Expo Go 直接可看）

- 模式联动大数字：定时跳 `00:30`（已有）/ 定数跳 `500` 个 / 花样跳 占位 / 自由跳 `00:00`
- 目标卡片与运动选择之间加一条提示条：
  - 定时跳、定数跳 → 浅紫底 `本模式含 AI 动作分析，结束后可在回放中查看评分`
  - 花样跳、自由跳 → 浅灰底 `本模式为纯计数（不含 AI 动作分析）`
- 顺手清掉切换模式时那句「动作库待接入」——现在切过去数字真的会变，再弹这句就是误导

**状态：待确认 → 实施**

### 批 2｜相机 + 计数（硬门槛：要转 Development Build）

- 依赖：`react-native-vision-camera` + `react-native-worklets-core` + `react-native-mediapipe-posedetection` + `zustand`
- 3-2-1 倒计时 → 计数页：超大计数、取景虚线框、节奏波形图、三类提醒、录像指示
- 计数状态机 + 滞回阈值，先在调试模式里校准（跳 30 次，误差 ≤ 10%）
- **不画骨架**

**状态：未开始（需先决策 dev build）**

### 批 3｜结果页 + 录像回放

- 结果页：次数 / 用时 / 平均速度 + 庆祝动画 + 回看入口
- 录像：四种模式都录，存本地
- 回放页：播放 / 进度 / 存相册 / 分享，内容区可滚动

**状态：未开始**

### 批 4｜AI 评分 + 7 部分报告

- 五个维度规则化打分（手臂 / 膝盖 / 躯干 / 跳跃高度 / 节奏稳定），阈值真机标定
- 回放页下方的详细报告：总评卡、六项关键数据、五维详解、节奏曲线、优势与改进、关键帧、免责
- 所有数值由算法算，**不写死演示数据**

**状态：未开始（依赖批 2 的真实数据）**

## 五、需要用户拍板的三件事

2. **「成绩」按钮后面接什么**：训练记录页 / 历史列表 / 数据统计？这是「历史记录类功能」最自然的落点，但要他定
3. **是否接受转 Development Build**：vision-camera 必须走 dev client，Expo Go 从此用不了。
   影响面说清楚——**不是每次都重打包**：dev build 装一次，之后改 JS 照常热更新（手机连 Metro 即可），只有改原生依赖或权限才需要重打。

## 六、风险与限制（提前说，不埋雷）

- **AI 评分的数值我看不到真机**：阈值必须他本人跳 30 次来标，我只能把「可标定」的框架搭好
- **摄像头逐帧识别 + 录像同时跑**：中低端机可能发热降帧，需要降识别帧率（15–30fps）、降录像分辨率
- **计数准确度**：挥手、整理衣服可能误计，靠最小间隔 + 滞回阈值压，但不可能 100%
- **视频只在本地**：换手机/卸载即丢
