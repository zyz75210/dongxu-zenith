# 出安装包 · 概念笔记

> 整理自 2026-11-24 凌晨的五个疑问。以后忘了就翻这份，不用重新问一遍。
>
> **一句话版**：源码存 GitHub（存档室），安装包存 Expo（代工厂），钥匙是进代工厂的通行证，三者互不影响。

---

## 速查三句话

1. **安装包永远不会进 GitHub**，那里只有源码。
2. **下载到本地的 apk 永久有效**，只有云端的下载链接会过期（过期去 Builds 列表重新下载）。
3. **钥匙过期不影响已经做好的包**，换一把新的就能继续出包。

---

## Q1：安装包会不会出现在 GitHub 上？

**不会。**

判断只看看域名：

| 域名 | 是什么 | 里面有什么 |
|---|---|---|
| `github.com` | 代码仓库 | 源码、提交历史、tag。**没有安装包** |
| `expo.dev` | Expo 控制台 | 构建记录、APK 下载入口 |
| 一串随机字母的 CDN 域名 | 文件托管服务器 | 真正的 apk 文件 |

> 之所以会“看着像”，是因为 EAS 的构建页地址里有项目名（`.../projects/CalendarApp/builds/...`），和仓库名太像。看域名就不会混。

---

## Q2：安装包会不会过期？

分三种“存在形式”，答案不同：

| 存在形式 | 会不会过期 | 说明 |
|---|---|---|
| 下载到电脑/手机上的 apk 文件 | **不会** | 它就是个文件，和照片、文档一样永久 |
| Expo 给的下载链接 | **会** | 链接有时效，过期打不开 |
| Expo 服务器上的构建记录 | **会** | 免费计划有保留期（一个月量级），到期被清理 |

**链接过期怎么办（不用重新出包）**

1. 打开 https://expo.dev
2. 左侧菜单点 **Builds**
3. 找到那一次构建，点进去
4. 右侧 **Download**，重新下载

**结论**：包一出来就下载到本地，并且**自己再备份一份**（网盘 / `D:\备份\`）。云端的东西是租来的。

---

## Q3：GitHub 和 Expo 是什么关系？

**两家完全独立的公司，没有隶属关系。** 只是碰巧都跟这个项目有关。

开饭店的类比：

| 现实里的东西 | 项目里对应的 |
|---|---|
| 菜谱（怎么写这道菜） | **源码**，那些 `.tsx` 文件 |
| 档案室（每版菜谱都存档，能翻旧版） | **GitHub** |
| 代工厂（按菜谱做成品） | **Expo 云端** |
| 门禁卡（进工厂要刷卡） | **钥匙 / token** |
| 做好的成品菜 | **APK** |
| 试吃台（不出厂也能尝） | **Expo Go**（扫码看效果那个 App） |

**唯一的联系**：同一份源码有两个副本——GitHub 上那份是版本存档，Expo 构建时用的是你电脑上那份的临时快照。GitHub 那份坏了不影响出包，反之亦然。

> `app.json` 里的 `projectId` 是 Expo 给项目编的号，和 GitHub 无关。

## Q4：钥匙过期了怎么获取

### A. Expo 钥匙（出包用）

1. 打开 **https://expo.dev/settings/access-tokens**（先登录 `zyzok`）
2. **Access tokens** 一栏 → **Create token**
3. 名字随便写，如 `zenith-apk-2026-11` → **Create**
4. **立刻复制**（这一页关掉就再也看不到，只能重新生成）
5. 回 VS Code 打开 `.env.local`，把 `EXPO_TOKEN=` 后面换成新的，`Ctrl + S`
6. 双击 `出安卓包.cmd`，看到 `Checking token ...` 下面出现 `zyzok` 就是换好了

**作废旧钥匙**：同一页面每个 token 右边有 **Revoke**。作废不影响已出好的包。

### B. GitHub 钥匙（推代码用）

1. 打开 **https://github.com/settings/tokens**
2. **Generate new token (classic)**
3. Note 写 `zenith-push`，Expiration 选 **90 天**（别选 No expiration）
4. 权限只勾 **`repo`**，别多勾
5. 拉到底 **Generate token**，复制 `ghp_...`
6. 用法：`git push` 弹窗要密码时，用户名 `zyz75210`、密码栏粘它

**平时用不到**——这台电脑已存在 Windows 凭据管理器里，只有换电脑或凭据失效才会问。

## Q5：整套概念（三个身份 + 两个 Expo）

**① 源码 —— 唯一的真身**
`E:\workbuddy任务文件夹\任务一\CalendarApp` 里那些文件。**只有它改了，App 才会变。** GitHub 和 Expo 上的都是它的复制品或快照。

**② GitHub —— 存档室，管“历史”**
每次改完推一份上去。作用：能翻回任何旧版本、换电脑能拉下来、以后多人协作有共同地盘。**不参与“做出安装包”。**

**③ Expo —— 代工厂，管“成品”**
本机没装安卓开发工具（JDK、Android SDK，2-3GB），做不了安装包。Expo 云端有配好工具的机器，你给源码 + 钥匙，它编译并把 apk 放在自己服务器上给你下载。

**钥匙为什么存在**
云端不认识你，钥匙证明“这单是 zyzok 下的”。它**只在启动构建那一刻被检查一次**。构建开始后，钥匙就和这个包没关系了——所以钥匙过期、作废、换新，都不影响已做好的包。

**钥匙为什么能有好几把**
它不是密码，是通行证。一台电脑一张，丢一张只作废那一张。所以推荐：**用完作废、下次再生成**，即使泄露也只是一次性的。

**两个 Expo 别混**

| | Expo 云端 | Expo Go |
|---|---|---|
| 是什么 | 出安装包的服务器 | 手机上的一个 App |
| 要钥匙吗 | 要 | 不要 |
| 干什么用 | 编译出 apk | 开发时扫码运行代码，快速看效果 |
| 能给别人吗 | 能（装 apk） | **不能**，别人手机上没装 Expo Go 就打不开 |

## 附：token 泄露了怎么处理

1. **GitHub token**：立即去 https://github.com/settings/tokens 点 **Delete**。classic token 带 `repo` 权限 = 所有仓库读写权，泄露风险最高。要用再生成。
2. **Expo token**：去 https://expo.dev/settings/access-tokens 点 **Revoke**。已出的包不受影响。
3. **以后怎么安全地给**：不要贴在聊天里。写进 `.env.local`（已被 git 忽略，永远进不了仓库），或者在自己终端里 `$env:EXPO_TOKEN="..."` 后直接跑构建。
4. **验证 token 有没有效、属于谁**：`npx eas-cli whoami` —— 打印出账号名就是有效的。
