# 动序ZENITH

一个跳绳主题的个人日历 App —— 看日期、记日程、点完成、留历史。

用 Expo + React Native 构建，同一套代码跑安卓与 iOS。当前版本 **1.3.0**。

> 版本说明见 `docs/更新日志-v1.3.0.md`，待办与设计取舍见 `docs/下次开工清单.md`，测试用例见 `docs/测试清单-v1.3.0.md`，新开任务怎么接上上下文见 `docs/换新任务怎么办.md`，出包相关概念见 `docs/出安装包-概念笔记.md` 和 `docs/怎么出安卓安装包.md`。

## 功能

- **日历主页**：真实日期、周一开头、上下月切换、左右滑动切月；点年月弹滚筒选择；选中日期有液体位移动画
- **底部导航**：一个深色小球在五个 tab 之间滑动（横向弹簧 + 拉长回弹的液体感）；图标是「灰底 + 跟着小球走的白色裁剪层」两层叠出来的 —— 球盖到哪白到哪，没盖到就是灰，盖住一半就白一半。颜色完全由小球的位移驱动（同一个 Animated 值、native driver），没有定时器、没有状态翻转，所以快速来回切也不会闪。两条实现约束别动：反向位移用 `interpolate([0,1]→[0,-1])` 而**不是** `Animated.multiply`（派生节点在部分安卓机上不跟 native 动画同步）；小球和白层是独立的 memo 组件、props 里没有随 tab 变化的东西，切页时不重渲染（否则重渲染会把落后的 JS 位移写回原生层，白块闪回上一个图标）；白层的水平/垂直位置**不靠 `onLayout` 测量值定位**（`item.x + icon.x` 两段各自取整再相加，和整体布局取整会差 1px，白字旁边露出灰字笔画 = 重影），而是用与灰层同一套 flex 布局（同宽容器 + 五个等分格 + 34 框两级居中 + 同一个 `PAD_TOP`）重新算一遍，测量值只用来挪小球
- **日程管理**：三类训练 + 休息（跳绳 / 体能 / 跑步 / 休息），日期与时间走同一套滚轮；支持新建、编辑、删除，支持每天 / 每周 / 每月重复（一次排满一年，逐条独立实例、共用 seriesId）
- **完成打卡**：主页右侧类型胶囊与详情页圆形按钮三态（未完成 / 已完成 / 超时），可直接点切换
- **本地提醒**：开启提醒的日程在开始前 15 分钟收到本地通知，不依赖网络；距开始不足 15 分钟的改为开始时提醒，已打卡完成的不再提醒；设置页可查看已排程条数并发送测试通知
- **通知体检**：开启提醒时检查权限与安卓渠道，哪里卡住就弹对应的引导（权限未开 / 渠道被关 / 省电策略），而不是把人直接丢进系统设置
- **训练页**：跳绳 + 户外跑步 + 户外骑行三种运动。跳绳下是目标时长（5 分钟 ~ 12 小时，± 5 分钟微调；**点数字弹出时/分滚轮**，与日历选年月日同一套面板，浮层同样在 App 最外层渲染、不套 Modal）+ 四种跳法（定时跳 / 定数跳 / 花样跳 / 自由跳），底部 音乐 / GO / 成绩（成绩之后进历史记录）；跑步与骑行暂时没有计时方案：跳法位置留四个等宽空胶囊、中间显示「功能还在开发」，跳绳那一屏不受影响
- **历史日程**：按月 → 按天 → 当天三层折叠，支持批量选择删除
- **个人资料**：头像从相册导入，名字 / 昵称 / 邮箱 / 生日可编辑；统计数字按真实日程计算
- **我的总览卡**：已添加 / 已完成 / 连续天数三个数字在上，数据报告、云同步两个入口并排在下面（报告入口直接显示本月完成率）
- **数据报告**：按月看完成率（环形进度）与类型分布（横向条 + 占比），可往前翻月份；完成率 = 该月已完成 / 该月日程总数，不把空白日算进分母
- **内容库**：「内容」tab 是内容库首页，首张卡是「跳绳花样段位制」——一段到九段的阶梯条（点亮的段是实心白、已解锁未点亮是半透、没碰过是灰）+ 已点亮段位数，标签为 基础 / 步伐 / 多摇，点进去是段位地图
- **段位地图**：官方九段 90 个动作（分区标题只写 基础区 1-3 / 进阶区 4-6 / 高阶区 7-9），段位卡可展开展示本段动作与前置；按能力标签筛选；点动作看编码、前置、Drill 三步、通关标准与示范视频位。头部三个数：已点亮 / 掌握动作 / 累计积分（积分按段位分级：一~三段 5 分、四~五段 10 分、六~八段 20 分、九段 30 分；九段满分 1,420）
- **段位进度**：动作可标记「已掌握」。三档门槛分开：**解锁**=上一段掌握过半（8 个动作里 4 个）、**点亮**=本段剩余未掌握 ≤2 个（段位卡、徽章墙、首页阶梯条同时点亮）、**通关**=整段全部掌握。所以「能挑战」「点亮」「通关」是三件事，点亮不等于通关；进度单独存在 `zenith.grades.v1`，不参与日程那份 schema（读坏了最多回到一段，不影响日程）
- **积累页**：「积累」tab 是运动置顶版布局——最上方是「我的运动」置顶卡（步数 / 千卡 / 分钟 + 14 根柱），下面「我的组件」是等高网格：大板块通栏、小板块半栏，两个小的并排正好一个大板块（全页只有 150 一种高度）。右上角是等大的「编辑」与「更多」两个圆钮（36×36，与训练 / 星球两页共用 `components/HeaderCircle`）。**这一版入口全部未接**：卡片、编辑、更多点击只给提示，不跳页；编辑模式留了端口（`GrowthScreen` 的 `HEIGHT` / `WIDGETS` 就是布局数据），等交互定下来再接
- **统一转场**：整屏「起雾 → 对焦」，全 App 只有一层模糊（`FrostOverlay`）；压暗层盖整屏（底部菜单栏也一起压暗），模糊层只到菜单栏上沿（图标不发毛）。不做任何位移。整屏轻压一层冷灰薄雾（峰值 7%，一条连续的“呼吸”曲线：起点/顶点/终点速度都为 0），二级页面 110+200ms、切 tab 90+170ms，节奏参数集中在 `src/motion.ts`。**原生模糊默认关闭**（Expo Go 里抓快照会和当前帧错位、看起来在闪），想要真模糊把 `MOTION.useBlur` 改成 true，建议等正式包

- **顶部按钮约定**：每个页面右上角的圆钮只服务本页（本页设置 / 本页编辑），页面之间暂时不互通。外观统一共用 `components/HeaderCircle`（36 圆 / 图标 18），**行为不共用**——`onPress` 由各页自己写，不抽成跨页复用的 handler，也不许用 A 页的按钮改 B 页的东西。这样后期功能变多时不会出现「点一个按钮牵动多页」的编辑混乱

## 本地运行

```bash
npm install
npx expo start -c --lan      # 手机装 Expo Go 扫码
```

手机卡在下载 bundle 时，是电脑上有 VPN / 虚拟网卡让 Expo 选错了网卡，固定到 Wi-Fi 地址即可：

```powershell
$env:REACT_NATIVE_PACKAGER_HOSTNAME="192.168.10.103"; npx expo start --lan
```

需要 Node 20+、Expo Go（SDK 58）。

类型检查：

```bash
./node_modules/.bin/tsc --noEmit
```

## 打包

```bash
npx eas-cli build --platform android --profile preview
```

默认构建会打出**四种 CPU 架构**的原生库（arm64-v8a / armeabi-v7a / x86 / x86_64），
其中 x86 与 x86_64 只服务于安卓模拟器（x86 平板极少），真机正常安装时用不到，
却占了安装包的 37MB。
`preview` 与 `preview-lite` 都用 `gradleCommand` 显式限定架构，只打真机需要的：

| profile | 架构 | 适用 | 预计体积 |
|---|---|---|---|
| `preview` | arm64-v8a + armeabi-v7a | 所有真机（含少量 32 位老机） | ~36.7MB（-50%） |
| `preview-lite` | arm64-v8a | 只给 64 位机，体积最小 | ~24.3MB（-67%） |
| `production` | 全部（AAB） | 应用商店由 Play 按机型分发 | — |

```bash
npx eas-cli build --platform android --profile preview-lite   # 要最小就用这个
```

限定架构的写法是 `-PreactNativeArchitectures=...`（Gradle 项目属性，会覆盖
`android/gradle.properties` 里的默认值）。**代价**：这两个 APK 都装不进模拟器，
要在模拟器上跑请临时去掉该参数，或者直接 `npx expo start` 用 Expo Go。

`production` 保持 `app-bundle`：AAB 由 Play 在分发时按机型切分，四种架构不会都塞给同一台手机。

### 安装包体积构成（1.1.0 实测 74.2MB）

| 项 | 体积 | 说明 |
|---|---|---|
| `lib/` 原生库 ×4 架构 | 65.4MB | arm64 17MB + v7a 12MB + x86 19MB + x86_64 18MB；**唯一的大头** |
| `classes.dex` | 4.8MB | 已开 R8（`android.enableMinifyInReleaseBuilds=true`） |
| `res/` | 2.9MB | 其中两个图标字体 1.66MB（Ionicons 384KB + MaterialCommunityIcons 1.28MB） |
| `assets/` | 1.7MB | JS 包（Hermes 字节码，压缩方式为 Stored） |

我方代码只占其中约 1.7MB，所以「优化 JS 代码」对安装包体积的影响不超过 2%；
真正能压的是架构、字体、资源这几块。已经做的：限定架构（-37MB）。
还能做但**没做**（各有代价，等需要时再开）：

- **图标字体做子集**：只保留用到的几十个字形，1.66MB → 约 30KB。字形轮廓不变、显示效果不变，
  但需要改 `@expo/vector-icons` 的引用方式，且以后每加一个新图标都要重新生成子集，
  漏一个就会显示空白，必须在真机上逐个图标核过。
- **开 `useLegacyPackaging`**：原生库会被压缩进 APK（下载体积再小一半），
  但安装后要在 `/data` 里解压一份，**装完占的空间反而更大、首次启动更慢**，与「轻量」相悖，不建议。
- **关掉 GIF / WebP 解码器**（`expo.gif.enabled` / `expo.webp.enabled`）：约 -0.8MB，
  但要保证以后不从相册选这两种格式的头像。

## 运行时开销

真机上「重不重」取决于三件事：启动时建了多少视图、状态变化时重渲染了谁、空闲时有没有东西在跑。

- **二级页首次打开才建视图树**（`components/SlideScreen` 的 `seen`）：启动时只建当前 tab，
  「我的 / 编辑资料 / 报告 / 段位地图 / 设置 / 历史 / 详情 / 添加」八页都不建。
  建树落在 `visible` 变真那一帧，被整屏起雾盖着，且起雾 / 对焦跑 native driver，
  JS 忙这一下不影响动画。打开过之后与原来一致：常驻、`display:none` 藏起来，不卸载。
- **常驻页全部 `memo`**：训练 / 内容 / 积累 / 星球 / 报告 / 段位地图的 props 都是
  `useCallback` / `useMemo` 固定住的，App 侧任何状态变化（轻提示、面板开关、量到导航栏高度）
  都不会带着它们重渲染。新增页面时记得同样包 `memo` + 稳定 props，否则这几百个视图会被白 diff 一遍。
- **浮层收起时一个视图都不留**：日期 / 时间 / 时长 / 通知引导四个面板都是 `mounted === false` 时
  `return null`，不是藏起来。
- **转场层常驻但不干活**：`FrostOverlay` 只留一个透明容器，内容（压暗层 / 模糊层）只在转场那几百毫秒挂出来。
- **没有常驻动画**：全 App 没有 `setInterval`、没有 `Animated.loop`、没有逐帧轮询，
  静止时 JS 线程和 GPU 都不做事。这一点改代码时别破坏 —— 加常驻循环动画是最容易把「轻」丢掉的方式。

## 已知限制

1. 头像存的是相册缓存目录的 uri，系统清缓存或覆盖安装后会失效（回落内置头像）。日程数据不受影响。
2. 「我的」页的 L9 徽章与「加入 428 天」是装饰文案；云同步、隐私与安全、帮助与反馈仍是占位入口（点了给提示）。数据报告已可用。
3. 运动类的「训练内容」虚线胶囊只给提示，不存数据。
4. 只有本地通知，没有远程推送（Expo Go 在 Android 上也不支持推送）。
5. 训练页目前是界面骨架：跳法 / 运动类型能切换但不保存，GO、音乐、成绩、更多运动都只弹提示；定数跳 / 花样跳的中间面板还是「目标时长」，按次数 / 套路计量的规则没定。跑步与骑行只留了四个空胶囊占位。
6. 内容库的「问问我」还没接问答，点了给提示；段位进度只在本机，不跟账号同步；段位地图暂不支持搜索与「个人理解」笔记（设计稿里的开发者编辑模式没搬进 App）；动作详情里的「示范视频」目前是占位框（显示「制作中」），还没有视频可放。
7. 积累页是纯版式：所有卡片与「编辑 / 更多」都只弹提示，数据是设计稿示意值（不是真实运动记录），编辑模式（拖动排序 / 移除 / 添加小组件）按需求暂不开放。
8. 转场的模糊效果在安卓 12 以下不生效（系统没有 RenderNode 模糊），会退化成一层半透明白雾；功能与节奏不受影响。系统状态栏（时间 / 电量）由系统绘制，App 内的模糊盖不到它。

其余待办与实现细节见 `运行说明.md` 与归档目录里的《开发交接文档》。
